# 产品与设计原则（App 版）

> **这不是一个网站，而是一个装在手机上的远控 App（Web 实现）。**
> 单用户、单机、手机优先、闭环交付。
>
> 任何功能、界面、接口、运维动作，先过这十条；与细则冲突时以原则为准。
> 例外必须写明：违反哪条、为什么、范围多大、什么时候复核。

## 网页思维 vs App 思维

| 网页思维（已否决） | App 思维（目标） |
|---|---|
| 每个 tab 是一个 HTML 页面，点击整页刷新 | 一个壳、多个视图，导航不重载 |
| 导航分散在各页/各侧栏 | 全局只有一个导航面 |
| 页面切换丢状态 | 视图常驻或状态存储，切回原样 |
| 会话属于页面，离开即断 | 会话属于 App，切视图不断 |
| 页面各自一套侧栏 | 页面内用 sheet/面板，不做第二套导航 |
| 浏览器后退 | App 导航栈 + 硬件返回 |
| 桌面一套、手机一套 | 同一 App 的自适应布局 |

## 十条原则

### 1. 单壳多屏，导航不重载

- 全局外壳只渲染一次；切换模块是**视图切换**，不是文档跳转。
- 点击 tab 不出现白屏、不重新拉全站资源、不丢滚动位置。
- URL 仍然可深链，但由 App 的导航栈管理，不靠整页刷新。

### 2. 只有一个导航面

- 同一时刻只允许一个全局导航面：手机底部 4 项 + 更多；桌面顶部栏。
- 页面内不得再出现第二套常驻侧栏；会话列表、主机列表、SFTP、控制键一律用**可关闭的 sheet/面板**。
- **违反信号**：终端页有全局栏 + 会话侧栏；移动端抽屉盖住底部 tab。

### 3. 视图常驻，会话不断

- 终端/SSH 的 WebSocket 由 App 的会话层持有，不随视图卸载断开。
- 切到文件、再切回终端，会话、滚动、输入状态原样恢复。
- 视图可以懒加载，但"已打开过的视图"不应被销毁重来。

### 4. 内容优先，chrome 退让

- 不做常驻左侧栏。桌面用 56px 顶栏；手机用 60px 底栏；内容占满剩余空间。
- 页面级侧栏（文件快速访问）默认收起，按需展开并记住偏好。
- **违反信号**：1920 宽屏上正文从 x=428 才开始；手机首屏被抽屉占掉一半。

### 5. 拇指设备与输入安全

- 主操作在底部拇指区；动作放 bottom sheet；触控目标 ≥44px。
- 输入控件移动端字号 ≥16px（防 iOS 聚焦放大）；弹层避让键盘与安全区。
- 不依赖 hover；长按 = 菜单；滑动不做隐藏手势。

### 6. 无死路

- 任何全屏视图必须有一个显式的返回/主页出口，且硬件返回可用。
- 全局底部 tab 在会话页也保持可见；不做"进入终端就换一套外壳"。
- **违反信号**：移动端 SSH 只剩侧栏底部的"概览"链接。

### 7. 动作跟随对象

- 文件出现在哪（收件箱/搜索/最近/案例），同一套动作就在哪；问 AI 是文件的头等动作。
- 聚合视图是"位置"，不是新页面；动作表只有一份。

### 8. 闭环才算功能

- 每个功能回答四件事：从哪进、做完在哪看、结果怎么拿走、失败怎么知道。
- 半个闭环（只上传不回收、只执行不反馈、只创建不管理）不算交付。

### 9. 状态各归其位

- 静态配置 → `config.json`；实时会话 → 守护进程；用户数据 → 状态目录；
  App 只保存 UI 状态（当前视图、滚动、上次目录）到本地存储。
- 写状态原子化；web 重启不丢会话；守护重启只影响自己。

### 10. 危险慢、可观测、技术克制

- 关机/删除/结束进程：二次确认、审计、可取消；音量/截屏/发文本：一键。
- 每个服务有 health/version/diagnostics；每个动作写事件；发布有预检/备份/冒烟/回滚。
- 只加一个人能运维的技术；不引入 Redis/容器/前端构建链，除非解决真实瓶颈。

## 已否决的设计（不要再提）

- 常驻左侧导航栏（占宽、导致双层侧栏）。
- 页面级第二套导航（会话侧栏、SFTP 侧栏叠加在全局栏旁边）。
- 会话页隐藏全局导航。
- 每个模块一个 HTML 页面、整页跳转。
- 复制动作表、复制格式化函数。

## 新功能准入五问

1. 它属于哪个**视图**？切过去会整页重载吗？
2. 导航面在哪？会不会出现第二套导航？
3. 切走再回来，**状态和会话**还在吗？
4. 手机上从进入到完成几步？**返回路径**是什么？
5. 需要新页面/新服务吗？能不能作为现有视图或 sheet？

## 验收底线（每次改 UI）

- 320 / 390 / 768 / 1440 四个宽度截图与几何检查。
- 切换 tab 不整页刷新（可用 PerformanceNavigationTiming 验证）。
- 会话页底部导航可见；任意全屏视图有返回。
- 列表滚动不把页面撑长；输入不越界、不被键盘遮挡。
- 无 console 错误、无横向滚动。

## 与细则的关系

代码结构（高内聚/低耦合、文件预算、依赖方向）另见 **`docs/code-structure.md`**。

```
principles.md（本文件：App 级原则）
   └─ ui-rules.md（具体排布/交互；迁移期以本文件为准）
        └─ 视图代码
```

- 不符合原则：不做，或先改原则。
- 符合原则但不符合细则：改细则并说明。
- 旧的多页壳在迁移完成前只做 bugfix，不再做布局演进。
